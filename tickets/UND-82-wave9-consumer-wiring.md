# [UND-82] wave 9 후반 계약 4건을 화면에 잇는다

> wave 9d · 사이즈 M · 의존 UND-75 · UND-76 · UND-77 · UND-78 · 소유 `di/AppComponent.kt` · `presentation/preferences/`

## 작업 내용 (설계 의도)

UND-75~78 은 각자 계약·구현까지만 만들고 **화면에 닿지 않는다.** 넷 다 `di/AppComponent.kt` 에
등록해야 하는데, 그 파일 하나를 네 티켓이 동시에 고치면 머지가 깨지기 때문이다 (결정 G34).
이 티켓이 그 배선을 **한 번에** 한다.

**계약만 만들고 잇지 않으면 UND-79 가 고쳐야 했던 상황을 넷 더 만드는 것이다** — 값은 있는데
아무도 부르지 않는 코드. 그래서 이 티켓은 후속이 아니라 그 wave 바로 다음이다.

### 배선 대상

1. **`AccountPreferencesState` 를 `updateProfile` 로 전환한다 — 이것이 첫 항목이다.**
   지금 프로필 수정은 `deleteProfile` → `saveProfile` 순서이고, 그 사이에 실패하면 **프로필이
   사라진다.** 보상 경로가 있지만 보상 자체가 실패할 수 있다. UND-76 이 원자적 계약을 만들어 두므로
   여기서 호출부를 바꾸고 **보상 경로를 지운다** — 유실 결함은 이 전환으로 비로소 닫힌다.
2. **git 설정 실효값**(UND-75) — `GitPreferencesContent` 가 각 항목의 실효값과 출처(저장소·전역·앱)를
   보여준다. Git 양쪽에 값이 없으면 앱 설정 값을 앱 출처로 표시한다 — **결합은 화면이 한다**
   (게이트웨이는 Git 만 안다).
3. **고정폭 서체 후보**(UND-77) — 서체 이름 입력을 후보 목록에서 고르는 형태로 바꾸되,
   **직접 입력을 없애지 않는다.** 열거가 실패해도 이름을 타이핑해 쓸 수 있어야 한다.
   저장된 값이 목록에 없어도 지우지 않는다.
4. **로그 디렉터리**(UND-78) — 고급 탭에서 위치를 보여주고 파일 관리자로 연다. '아직 없음' 이면
   열기 동작을 비활성화한다.

### 지켜야 할 것

- 화면은 UseCase 만 부른다 — Gateway 직접 주입은 위반이다.
- 네 화면은 서로 다른 탭 파일이라 이 티켓 안에서도 파일이 겹치지 않는다. 겹치는 것은
  `di/AppComponent.kt` 하나이고, 그래서 한 티켓이다.

**롤백**: 배선 추가라 revert 로 끝난다. 다만 1번 전환을 되돌리면 유실 경로가 되살아나므로,
되돌릴 때는 2~4 만 떼어 낸다.

## 테스트 케이스
- 프로필 이름을 유지한 채 이메일을 바꾸면 원자적 수정이 호출되고 `deleteProfile` 은 호출되지 않는다
- 수정 저장이 실패해도 기존 프로필이 그대로 남는다
- git 설정이 저장소·전역 어디에도 없으면 화면이 앱 설정 값을 앱 출처로 표시한다
- 저장소와 전역에 모두 있으면 저장소 값을 저장소 출처로 표시한다
- 서체 열거가 실패해도 이름 직접 입력으로 값을 저장할 수 있다
- 저장된 서체가 후보 목록에 없어도 값이 유지된다
- 로그 디렉터리가 없으면 폴더 열기 버튼이 비활성화된다
