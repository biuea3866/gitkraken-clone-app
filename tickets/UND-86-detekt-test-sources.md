# [UND-86] 테스트 소스에도 정적 분석을 적용한다

> wave 11 · 사이즈 M · 의존 없음 · 소유 `build.gradle.kts`(detekt 설정) · `config/detekt/` · `app/src/test/**`

## 작업 내용 (설계 의도)

`detektTest` 가 `build` 에 걸려 있지 않다. `app/src/test` 에 **157 weighted issues** 가 쌓여 있고
그것이 빌드를 막지 않는다 — **테스트 소스에 정적 분석이 사실상 적용되지 않는 상태**다.

테스트는 이 레포에서 가장 많이 늘어나는 코드이고(현재 2458건), 지금까지 여러 티켓이 테스트에서
결함을 냈다 — 잘못된 블록 치환으로 엉뚱한 테스트가 지워진 적, 집합 비교로 사라짐을 못 잡은 적,
이름이 하지 않는 일을 말한 적이 있다. **검사를 안 도는 코드가 검사의 근거**인 상태다.

### 하는 일

- `detektTest` 를 `build` 의 검증 경로에 넣는다.
- 기존 157건을 **한 번에 고치지 않는다** — baseline 으로 고정하고 **신규 코드에만 적용**되게 한다.
  전량 수정은 이 티켓의 크기를 넘고, 고치는 과정에서 테스트 의미를 바꿀 위험이 있다.
- baseline 에 남은 항목 수와 그것을 줄이는 방법을 산출물에 적는다 — baseline 은 **영구 면제가
  아니라 빚 목록**이다.

**롤백**: 빌드 설정 변경이라 revert 로 끝난다. 되돌리면 테스트 소스가 다시 검사 밖으로 나간다.

## 의존
- 없음

## 테스트 케이스
- 신규 테스트 코드가 detekt 규칙을 어기면 `./gradlew build` 가 실패한다
- baseline 에 올라간 기존 항목은 빌드를 막지 않는다
- baseline 에 없는 새 위반은 baseline 파일을 고치지 않고는 통과할 수 없다
