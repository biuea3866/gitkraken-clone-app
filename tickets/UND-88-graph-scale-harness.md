# [UND-88] 대형 저장소에서 그래프가 버티는지 재는 수단을 만든다

> wave 12 · 사이즈 M · 의존 없음 · 소유 `app/src/test/kotlin/dev/undine/bench/` · `.agent/scripts/`(벤치 저장소 생성)

## 작업 내용 (설계 의도)

**대형 저장소 성능을 다루는 티켓이 하나도 없다.** 커밋 이력에 페이징(UND-03)은 있지만, 수만 커밋에서
레인 계산과 스크롤이 버티는지 확인한 적이 없다. GitKraken 과 비교되는 지점이 정확히 거기다.

임시로 재 본 결과(커밋 26,665 · 브랜치 806 합성 저장소, 200커밋/페이지):

| 항목 | 값 |
|---|---|
| 첫 페이지 로드 | 118ms |
| 첫 페이지 레인 배치 | 1ms |
| 이후 페이지 로드 | 중앙 67ms · P95 78ms · 최대 94ms |
| 이후 레인 배치 | 중앙 0ms · P95 1ms · 최대 1ms |
| 12,000커밋 레인 총합 | **11ms** |

**레인 알고리즘은 병목이 아니다** — `LaneCarry` 로 페이지 간 상태를 이어받아 뒤로 갈수록 느려지지
않는다. 병목은 JGit 이력 읽기다.

### 왜 티켓인가

그 측정은 **임시 코드로 한 번 재고 지웠다.** 남아 있지 않으면 다음에 누가 레인 알고리즘이나 페이징을
고쳤을 때 **느려진 것을 아무도 모른다.** 수치가 아니라 수단을 남기는 것이 이 티켓이다.

### 하는 일

1. **벤치 저장소 생성 스크립트** — `git fast-import` 로 결정적으로 만든다(고정 seed). 커밋 수·동시
   브랜치 수를 인자로 받아 토폴로지를 조절할 수 있게 한다. 저장소는 산출물이지 커밋 대상이 아니다.
2. **측정 스펙** — 이력 페이지 로드와 레인 배치를 **나눠** 잰다. 어느 쪽이 느려졌는지 구분되지
   않으면 회귀를 추적할 수 없다.
3. **기본 실행에서 제외** — 벤치 저장소가 있을 때만 돌게 한다(`@EnabledIf`). CI·일반 `build` 를
   느리게 만들지 않는다.
   - **시스템 프로퍼티(`-D`)가 아니라 환경 변수로 전달한다.** `-D` 는 Gradle 자신의 JVM 에만 붙고
     테스트 JVM 으로 가지 않는다 (임시 측정에서 실제로 걸린 함정이다).

### 임계값을 지금 박지 않는다

**기준선이 없는 상태에서 숫자를 정하면 그 값이 근거 없이 계약이 된다.** 이 티켓은 재는 수단과
첫 측정치를 남기는 데까지다. 임계값은 그 수치를 여러 번 본 뒤 별도로 정한다.

**롤백**: 테스트 스코프 추가라 revert 로 끝난다.

## 의존
- 없음

## 테스트 케이스
- 벤치 저장소가 없으면 스펙이 **건너뛰어지고** `./gradlew build` 시간이 늘지 않는다
- 생성 스크립트를 같은 인자로 두 번 돌리면 같은 커밋 그래프가 나온다 (고정 seed)
- 측정이 이력 로드와 레인 배치를 각각 별도 수치로 출력한다
- 페이지를 여러 장 읽어도 레인 배치 시간이 페이지마다 크게 늘지 않는다 (`LaneCarry` 회귀 감지)
