# [UND-85] 기록 순서 계약을 선택이 아니게 만든다

> wave 11 · 사이즈 S · 의존 UND-79 · 소유 `application/undo/OperationRecorder.kt` · 그 생성자 호출부

## 작업 내용 (설계 의도)

`OperationRecorder` 의 `changeRecordingOrder: ChangeRecordingOrder? = null` 이 **기본값을 갖는다.**
주입을 빠뜨리면 `recordingChange` 가 그냥 블록을 실행하고 **기록 순서 보장이 조용히 꺼진다** —
변경 A → 변경 B → B 기록 → A 기록 이면 최상단 A 의 기준 상태가 낡아 되돌리기가 거부된다.

지금은 앱 배선(`AppComponent`)과 시나리오 조립이 모두 주입하지만, **그것이 코드로 강제되지 않는다.**
새 조립 지점이 생기면 아무 경고 없이 보장을 잃는다.

**레포에 이 모양을 금지하는 결정이 이미 있다** (G5): 기본값을 두어 방어를 선택으로 만들면, 방어를
쓰지 않는 기록이 조용히 생긴다. `UndoStrategy.HardResetTo.expected` 에 기본값을 두지 않은 것과
같은 이유다.

### 하는 일

- 기본값을 없애고 **필수 인자**로 만든다.
- 단위 테스트가 `GitAccess` 없이 조립하던 자리는 **통과 구현**(블록을 그대로 실행하는 구현)을
  명시적으로 넘긴다 — "없어서 안 걸었다" 와 "일부러 순서를 안 건다" 를 코드에서 구분한다.

**롤백**: 시그니처 변경이라 revert 로 끝난다. 동작은 바뀌지 않는다 (지금도 실제 배선은 모두 주입한다).

## 테스트 케이스
- 순서 계약 없이 `OperationRecorder` 를 만들 수 없다 (컴파일 단위 — 호출부 전수 갱신으로 확인)
- 통과 구현을 넘긴 단위 테스트는 기존과 같이 동작한다
- 실제 배선에서 두 변경이 겹쳐도 기록 순서가 변경 순서를 따른다 (UND-79 회귀 유지)
