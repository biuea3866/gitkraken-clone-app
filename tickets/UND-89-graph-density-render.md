# [UND-89] 실제 이력으로 그래프를 렌더해 밀도를 눈으로 본다

> wave 12 · 사이즈 S · 의존 UND-88 · 소유 `app/src/test/kotlin/dev/undine/bench/`

## 작업 내용 (설계 의도)

`ScreenshotRenderSpec`(UND-56)이 그래프를 PNG 로 남기지만 **손으로 만든 6커밋 픽스처**를 쓴다.
해시가 전부 `0000000` 이고 레인이 둘뿐이라, 배지 색과 머지 곡선이 그려지는지는 보이지만
**레인이 여럿 열린 화면이 읽히는지**는 알 수 없다. 그것이 GitKraken 과 비교되는 화면이다.

UND-88 의 벤치 저장소를 **실제 데이터원**으로 써서 한 장 더 남긴다.

### 하는 일

- 벤치 저장소의 이력을 **전체 ref** 로 불러 렌더한다. `refs/heads/main` 만 넣으면 레인이 둘뿐이라
  이 티켓의 목적이 사라진다.
- **이력을 미리 읽어 두고 렌더한다.** 렌더러의 프레임 루프는 `Dispatchers.IO` 의 로드를 기다려 주지
  않아, 실제 Gateway 를 그대로 물리면 "이력을 불러오는 중" 화면이 찍힌다(임시 확인에서 실제로 겪었다).
  데이터는 실제 저장소 것을 쓰되 읽기만 먼저 끝낸다.
- **ref 배지가 보이는 구간**을 고른다. 임시 확인에서는 브랜치 팁이 화면 밖이라 배지가 한 장에도
  뜨지 않아 **배지 밀도를 확인하지 못했다.**

### 이 티켓이 답하지 않는 것

렌더는 **사람이 보고 판단할 재료**를 남길 뿐 자동으로 통과/실패를 가르지 않는다. 색 대비·간격이
"읽히는가" 는 픽셀 단언으로 정할 수 없다 — 임계값을 만들면 그 숫자가 디자인 결정을 대신해 버린다.

**롤백**: 테스트 스코프 추가라 revert 로 끝난다.

## 테스트 케이스
- 벤치 저장소가 없으면 건너뛴다
- 렌더 결과에 **레인이 셋 이상** 나타난다 (둘뿐이면 밀도를 못 본 것이다)
- 렌더 결과에 **ref 배지가 하나 이상** 나타난다
- "이력을 불러오는 중" 상태가 아니라 커밋 행이 그려진 화면이 남는다
