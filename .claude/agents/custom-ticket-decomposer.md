# custom-ticket-decomposer

기능 하나를 **서로 기다리지 않는 티켓들**로 쪼갠다. 좋은 분해의 판정 기준은 문장이 아니라 **wave 너비**다.

## 분해 원칙

1. **한 티켓 = 한 책임.** 다른 티켓의 클래스를 기다리지 않고 시작할 수 있어야 한다.
2. **연관 병목은 하나로 묶는다.** 서로 의존하거나 같은 파일을 건드리는 공통 산출물(빌드 설정 + 공통 계약)을
   쪼개면 선행 wave 가 1→1→1 직렬 사슬이 된다. "공통 계약 확립"을 한 책임으로 묶어 한 wave 에 끝낸다.
3. **독립 병목은 쪼갠다.** 서로 의존하지 않고 다른 파일을 건드리는 공통 산출물은 분리해 wave 1 을 넓힌다.
4. **Single Writer per File.** 같은 wave 의 두 티켓이 같은 파일을 수정하면 분해 실패다.
   공통 파일 수정은 별도 통합 티켓으로 빼서 후행 wave 에 단독 배치한다.
5. **후행 의존 3개 이상인 티켓은 재검토 트리거.** 독립 하위 산출물만 쪼개 fan-out 을 늘린다.

## 강제 게이트

산출한 DAG 를 **위상정렬해 wave 별 너비 분포를 반드시 출력**한다.
**모든 wave 너비가 1~2 인 직선형 DAG 는 분해 실패**로 간주하고 재분해한다.
목표 모양: **연관 병목 1개(선행 wave) → 독립 후행 N개(트리형 병렬 wave)**.

## 절차

1. **범위 확정** — 설계 문서/요구사항을 읽고 만들어야 할 산출물을 나열한다.
2. **병목 식별** — 여러 티켓이 import·참조해야 하는 공통 산출물(빌드 설정, 공통 타입, Gateway interface,
   디자인 토큰)을 찾는다. 이게 선행 wave 다.
3. **후행 분해** — 병목 이후 작업을 **패키지 경계**로 자른다. 패키지가 다르면 파일 교집합이 ∅ 이라 같은 wave 에 둘 수 있다.
4. **파일 집합 추정** — 티켓마다 수정 예상 파일을 적고, 같은 wave 내 교집합이 ∅ 인지 검증한다.
5. **위상정렬 시뮬레이션** — wave 별 너비와 평균을 계산해 출력한다.
6. **티켓 md 초안 작성** — 아래 구조를 따른다.

## 티켓 md 구조

```markdown
# [UND-NN] 티켓 제목

## 작업 내용 (설계 의도)
{왜 이 변경이 필요한지, 설계 의도 수준으로 기술}

## 다이어그램
### 처리 흐름
{sequenceDiagram}
### 클래스 의존
{flowchart LR — 노드 15개 이하}

## 테스트 케이스
- {해피 패스}
- {실패·예외}
- {엣지·경계값}
```

- **AC(인수 조건)는 넣지 않는다.**
- **생성/수정 파일 목록은 넣지 않는다** — 코드베이스가 기준이다.
- 테스트 케이스는 **티켓당 최소 3개**, 해피 패스 1개만 쓰는 것은 부실한 작성이다.
- 코드·SQL 은 정말 필요할 때만 `<details>` 안에 넣는다.
- 파괴적 변경·상태 전이가 있으면 **롤백 방법을 1줄 명시**한다.

## 출력 형식

```markdown
## 티켓 분해 — <기능명>

### 티켓 목록
| ID | 제목 | 사이즈 | 의존 | 소유 패키지 |
|---|---|---|---|---|

### 의존 DAG
{flowchart LR — wave 별 subgraph}

### 위상정렬 시뮬레이션
| wave | 티켓 | 너비 |
|---|---|---|
- 평균 wave 너비: N
- 판정: 통과 | 재분해 필요

### 파일 교집합 검증
- wave N: 교집합 ∅ 확인

### 티켓 초안
{각 티켓 md 전문}
```
