# 예외 / 에러 처리 규칙

데스크톱 앱에는 "중앙 HTTP 핸들러"가 없다. **모든 실패는 결국 사용자 화면에 도달**하므로,
경계에서 도메인 예외로 번역하고 UI 가 읽을 수 있는 형태로 올린다.

## 공통 베이스라인

1. **3계층 흐름** — (1) infrastructure 가 JGit 예외를 잡아 **도메인 예외로 번역** →
   (2) UseCase 가 통과시키거나 결과 타입으로 감싼다 → (3) presentation 이 사용자 메시지로 렌더링한다.
   Composable 안에서 `try/catch` 를 흩뿌리지 않는다.
2. **JGit 예외를 UI 까지 그대로 올리지 않는다.** `TransportException` 메시지에는 원격 URL 이 들어 있고
   거기에 토큰이 포함될 수 있다. 번역하면서 마스킹한다.
3. **도메인 예외는 sealed 계층으로.** `UndineException` 아래에 실패 종류를 닫아 두면
   UI 가 `when` 으로 빠짐없이 처리할 수 있다.
4. **실패 종류를 구분한다.** 사용자가 할 수 있는 행동이 다르기 때문이다.

| 종류 | 예 | UI 처리 |
|---|---|---|
| 사용자 교정 가능 | 인증 실패, 충돌 발생, 더티 워킹트리 | 무엇을 해야 하는지 안내 |
| 재시도 가능 | 네트워크 타임아웃 | 재시도 버튼 |
| 상태 위반 | 이미 병합된 브랜치 삭제 | 왜 불가능한지 설명 |
| 버그 | 예상 못 한 예외 | 로그 수집 안내 + 원문 보존 |

5. **`CancellationException` 은 절대 삼키지 않는다.** 잡았으면 다시 던진다 —
   삼키면 코루틴 취소가 동작하지 않고 UI 가 멈춘 것처럼 보인다.
6. **부분 실패를 성공으로 보고하지 않는다.** 여러 참조를 갱신하다 일부가 실패하면
   성공 건수와 실패 건수를 함께 올린다.
7. **조용한 fallback 금지.** 실패 시 빈 목록을 반환해 "저장소가 비었다"처럼 보이게 만들지 않는다.

위반 중 2·5·7 은 조용한 실패라서 p2 이상이다 — [[custom-silent-failure-hunter]] 가 같은 축을 본다.
